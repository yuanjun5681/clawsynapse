# ClawSynapse 面向 Camind 的能力提升规划

最后更新：2026-10-20

> 状态：规划稿。本文基于当前代码审查与 Camind 平台设计需求，区分现有实现、能力差距与建议目标；不代表相关能力已经实现或通过生产验收。本文用于划定后续实施与验收范围，不替代详细协议设计。

通用 P0 的后续实施状态见 [能力改进路线图](./capability-improvement-roadmap.md)。本文“当前实现”部分保留建稿时的审查快照，不应覆盖后续代码与协议文档；完整生产设备验收矩阵仍未完成。

## 1. 目标与结论

ClawSynapse 继续定位为 Camind 的 Agent 通信层，为控制中心、云端支持 Agent 和设备 Agent 提供安全、可恢复、可查询的通信与文件交接能力，不扩展为另一套 Camind 业务后端。

当前实现适合继续开展集成验证，但不能仅凭节点互信、消息发布成功或 Agent 回复，就开放生产设备执行。生产设备通道接入前，优先补齐：

1. 覆盖完整请求语义的签名与限定范围授权。
2. 明确投递承诺、持久恢复、去重及过期控制。
3. 结构化业务关联、通信回执与状态查询。
4. 有签名内容绑定、接收约束及接收凭据的文件交接。
5. 生产凭据配置、本地接口保护和能力就绪判断。

优化重点不是增加更多 Agent Adapter，而是保证失败时能够准确说明发生了什么，并防止越权、重复动作和错误报成功。

## 2. 需求来源与适用范围

需求来源为 Camind 工作区的 `docs/camind-platform-design.md`，设计稿日期为 2026-10-19，重点对应：

- 第 2 章：租户、站点、身份、控制中心与设备协作。
- 第 4 章：程序传输、机床接收凭据与加工执行。
- 第 5 章：候选通信通道、业务幂等、Bot 审批和远程操作。
- 第 7 章：现场反馈、云端工单与获准研发证据。
- 第 8 章：断网、重启、结果未决与数据保护。
- 第 10 章：设备协作、隔离与故障恢复验收。

Camind 首期反馈仍经 Camind HTTPS API 持久受理，状态可轮询。ClawSynapse 是候选 Agent 通信实现，不因接入 Camind 就成为工单数据库、多租户业务平台或设备安全控制层。

本文所列源码位置以本次审查快照为准，后续代码变更可能导致行号变化。

## 3. 已有能力与需要保留的基础

| 已有能力 | 可复用价值 | 不能据此推导的保证 |
| --- | --- | --- |
| daemon 主动连接 NATS | 符合现场主动出站的连接方向 | 未证明所有厂网、防火墙和 TLS 部署均可用 |
| Ed25519 身份、认证挑战和节点信任 | 提供节点身份验证基础 | 节点可信不等于工程师授权或跨租户访问许可 |
| 信任撤销机制 | 可作为凭据及连接撤销体系的一部分 | 未替代 Camind 的站点停用、设备解绑和控制权移交 |
| 消息签名、类型路由和会话关联 | 可复用协议与路由结构 | 未提供完整 envelope 保护、持久投递和业务幂等 |
| Webhook 等 Adapter | 可接入 Camind 的确定性业务入口 | Adapter 接纳不等于业务受理或设备执行完成 |
| JetStream ObjectStore 文件传输 | 已具备对象存储和存储层 digest 校验基础 | 未具备签名业务 manifest 绑定和机床接收凭据 |
| CLI、日志、健康查询与系统服务管理 | 可复用运维入口 | 进程存活不等于指定通信能力就绪 |

## 4. 职责划分

| 责任方 | 应承担的职责 |
| --- | --- |
| ClawSynapse | 节点认证、通信权限、消息与文件交接、投递状态、过期控制、通信去重、通信审计 |
| Camind | 租户与站点业务归属、工程师身份与角色、审批、工单、证据授权、业务幂等、软件与资源启用 |
| 设备受限执行程序 | 目标设备与程序校验、执行前授权复核、实时条件检查、动作结果和机床接收凭据 |
| 设备安全系统 | 急停、门锁、互锁及经验证的本地安全策略 |
| NX 工作台集群 | 执行队列、节点路由、许可容量与执行资源调度 |

ClawSynapse 传递授权上下文，但不自行认定工程师已批准；传递执行结果，但不根据自然语言回复认定加工完成。

以下能力不纳入本项目的业务实现范围：工单状态机、工艺审批、Bot 账户系统、客户计费、NX 调度、现场开工条件判定和安全互锁。

## 5. P0：生产设备通道开放前必须完成

P0 表示生产设备通道的上线前置条件，不表示所有项目均须完成后才能开展隔离的只读支持试点。

### 5.1 完整请求签名与协议版本约束

**当前实现：** `internal/messaging/service.go:375–377` 的 `signatureInput()` 仅覆盖 `Type / From / To / Ts / Content / ID`，未覆盖 `Metadata`、`AgentID`、`SessionKey` 和 `ProtocolVersion`。

**风险：** 路由和扩展上下文没有获得同等签名保护。把租户、站点、业务 ID 或授权证据放入 metadata，不能自动获得完整性保证。

**目标：**

- 使用确定性编码，签名覆盖完整 envelope，排除签名字段本身；明确字段规范化与未知字段处理规则。
- 将目标、路由、业务关联、有效期、内容指纹和协议版本纳入保护。
- 拒绝不支持的版本、缺失必需字段及无法验证的请求，不静默退回较弱模式。
- 对签名正确的消息仍进行有效期、通信去重和权限检查；签名不能单独防止合法旧消息重放。
- 签名只证明发送节点，不替代工程师身份和具体业务授权。

**验收：** 修改目标 Agent、会话、租户、有效期、版本或业务指纹后必须拒绝；过期消息即使签名正确也不得进入执行入口。

### 5.2 从节点互信提升为限定范围授权

**当前实现：** `internal/messaging/service.go:87–105` 主要检查目标节点的信任与认证状态；`internal/protocol/messages.go:110–122` 未定义一等的租户、站点及动作授权结构。

**目标：**

- 将节点绑定到受控的租户、站点和允许访问的目标范围，归属由可信配置或签发方确认，不能直接信任发送方自行填写的标识。
- 对目标、消息类型和通信方向实施权限检查；明确人员、Agent 和设备身份的区别。
- NATS 配套 account／subject 权限，隔离消息、发现信息及文件对象访问；不以节点 ID 或文件名前缀代替隔离。
- 凭据撤销、设备解绑和站点停用后阻止新的未授权通信；已执行动作的安全处理由设备本地策略负责。
- Camind 与设备执行端继续验证工程师角色、具体审批、程序版本和实时条件。

**验收：** 一个已受信任节点仍不能跨租户投递、读取其他租户文件，或向未授权设备发送启动请求；拒绝测试同时覆盖消息、文件和发现通道。

### 5.3 明确可靠性承诺与持久恢复

**当前实现：** 普通消息经 `internal/natsbus/client.go:145–168` 使用 Core NATS 发布与订阅；`internal/messaging/service.go:218–230` 的最近消息仅保存在内存中，上限为 1000 条。当前消息路径没有持久 outbox、接收去重记录或业务有效期检查。自动重连不能替代离线投递与重启恢复。

**目标：** 按请求类别声明可靠性，不对所有消息统一离线排队和重试。

| 请求类别 | 投递与恢复原则 |
| --- | --- |
| 支持通知、获准证据交接 | 可持久投递，在有效期和授权范围内恢复；业务结果仍向 Camind 查询 |
| 审批、设备启动等时效敏感请求 | 不离线积压后自动执行；过期、连接代次或授权状态变化后拒绝 |
| 状态查询 | 可按原业务记录重新查询，不由查询触发原动作重做 |

实施时补齐持久发送记录、接收去重、确认、受控重试和状态查询。可利用 JetStream durable consumer，但必须同时明确本地接纳、broker 持久化、接收端记录与业务受理各自的承诺。存储方案需在详细设计中确定，不预设启用 JetStream 就自然获得端到端可靠性。

设备动作结果不明时，进入未决并查询原动作；不得由通信层自动重发启动。通信投递可采用至少一次语义，但不承诺物理动作的“exactly once”。

**验收：** 发送方、接收方或 broker 重启后状态可恢复；设备已执行但回执丢失时不自动重做；过期或离线启动请求不会在重连后补执行。

### 5.4 结构化关联、回执与业务幂等衔接

**当前实现：** `internal/messaging/handler.go:108–120` 将 Adapter 接纳转换为 `accepted` 文本；`internal/messaging/service.go:286–299` 的回信主要复用 `SessionKey`，未提供结构化原请求与业务阶段关联。

**目标：**

- 支持原请求关联 ID、业务 ID、内容指纹及目标范围，具体字段名在协议设计中统一确定。
- 区分本地持久接纳、对端持久接收、Adapter 接纳、拒绝、过期及结果未决。
- 工单受理、机床程序接收、设备执行完成由权威业务端提供可关联的凭据，不由通信回执推导。
- 提供结构化错误码、失败阶段和恢复建议；通信层的可重试不能越过业务端的动作重试约束。
- 支持按原请求查询。业务权威端对同一范围内的业务 ID 与内容指纹做持久幂等：指纹一致返回已有状态，指纹冲突拒绝。
- 通信层维护投递去重，不把消息 ID 去重当作完整业务幂等。

**验收：** 重复请求返回已有状态；同一业务 ID 更换内容被拒绝；HTTP 200、`.response` 或自然语言“完成”均不能单独形成设备完成结论。

### 5.5 安全、可验证的文件交接

**当前实现：**

- `internal/transfer/service.go:205–242` 在 ObjectStore 上传成功后将发送记录标记为 `completed`，文件通知发布错误被忽略，没有接收方持久确认。
- `internal/transfer/service.go:260–354` 使用通知提供的 bucket、对象头中的发送方与文件名进行接收和落盘；发送方为空时跳过对应信任检查，接收路径未落实与发送端对应的文件大小限制。
- 文件传输记录与接收去重主要保存在内存中，见 `internal/transfer/service.go:28–68,402–406`。

**完整性校验的准确边界：** 当前使用的 nats.go ObjectStore 在读取时提供存储层 digest 校验，读取错误会经接收流程传播并触发本地文件删除。不能表述为“完全没有 SHA 校验”。缺少的是发送方签名 manifest 与业务版本的端到端内容绑定。

**目标：**

1. 签名 manifest 绑定发送方、接收方、业务 ID、用途、SHA-256、大小和有效期；接收时以该 manifest 对照实际内容。
2. bucket 与对象归属必须验证，不能直接信任通知参数；对象头不得单独成为身份或授权来源。
3. 接收端验证文件名、目录与最终路径，防路径穿越、符号链接逃逸和覆盖已有业务文件。
4. 实施单文件、并发、总空间、磁盘余量及保留期限制，不能只限制发送端。
5. 临时文件完整接收并校验后原子交接；失败时不暴露为可用文件。
6. 持久保存接收记录和接收凭据，支持重启核对与并发重复接收抑制。
7. 区分云存储上传、边缘落盘和机床接收；ClawSynapse 只能证明自身交接阶段，机床接收凭据由设备端提供。
8. 文件已收到但通知 Adapter 失败时，交接状态可查询、通知可恢复，不能把文件副作用重复执行。

**验收：** 内容替换、恶意文件名、跨 bucket、超大文件、磁盘满、重启和重复通知均不导致越界落盘或假完成；签名 manifest 的内容指纹与落盘内容不一致时拒收。

### 5.6 生产凭据配置与本地接口保护

**当前实现：** `internal/api/server.go:58–79` 直接注册发布、信任管理及配置修改路由，没有鉴权中间件。默认 loopback 缩小暴露面，但不是本机进程间的权限隔离。`internal/natsbus/client.go:49–83` 未显式接入凭据文件、客户端证书等生产配置选项，不能仅凭运维文档列出相关配置就认定完整实现。

**目标：**

- 本地接口采用访问凭据或受 OS 权限保护的本地通道；明确哪些本机进程有权发布、批准信任和修改配置。
- 非 loopback 监听必须显式启用，要求认证和安全传输。
- 明确支持 NATS 凭据、证书验证、轮换和吊销，不通过日志或配置查询泄露敏感值。
- 提供生产配置检查，拒绝 `open` 信任模式及不符合要求的明文连接，不静默降级。
- 默认不记录消息正文；现有消息路径的正文预览日志需要调整，避免写入客户文件内容、业务秘密或敏感信息。

**验收：** 无权限本机调用方不能发布或修改信任；错误、过期或被撤销凭据被拒绝；生产配置不满足要求时无法以“已就绪”状态启动对应能力。

## 6. P1：可靠运行与集成能力

| 能力 | 当前依据／差距 | 目标与验收重点 |
| --- | --- | --- |
| 有界并发与背压 | `internal/messaging/service.go:233–283` 为每条投递启动 goroutine | 限制 in-flight、队列和负载；按会话或设备提供所需串行约束；积压不耗尽进程资源，也不让后续启动越过前置步骤 |
| 能力就绪状态 | `internal/api/handlers.go:107–162` 即使包含断连或 Adapter 不健康数据，顶层仍返回 `health.ok` | 区分存活、NATS 在线、文件通道、Adapter 和指定投递保证；Camind 按所需能力判断是否允许操作 |
| Camind Webhook 契约 | 已有 Webhook Adapter，可复用接入点 | 先持久受理再返回，业务结果异步查询；设备控制类请求进入受限执行程序，不直接变成 LLM 提示词 |
| 能力协商与兼容矩阵 | 协议版本存在，但不足以证明各项保证 | 固定受测版本组合；不支持持久投递、签名版本或有效期校验时拒绝，不静默降级 |
| 脱敏审计与指标 | 已有结构化日志及连接状态 | 关联业务、节点、投递阶段与错误；提供积压、过期、重试、拒绝和文件交接指标，不记录客户正文 |
| 文档与实现一致性 | 部署建议不等于已接入配置或已提供可靠性承诺 | 同步协议、配置、API、消息及集成文档，明确已支持、限制和部署前置条件 |

若设备 Agent 部署在 Windows 工控机，还须补齐 Windows 服务安装、权限、自动恢复、日志和升级回退验证。当前服务管理与安装路径主要覆盖 Linux/macOS，不能直接假设 Windows 已达到同等运维能力。该项由目标部署决定，不强制所有站点采用 Windows。

## 7. 分阶段实施顺序

### 阶段一：安全的只读支持通道

- 完成完整签名、本地接口保护、通信隔离和文件接收安全。
- 通过 Webhook 接入 Camind；工单仍由 Camind HTTPS API 持久受理。
- 仅承载支持消息、状态通知和获准证据，不开放生产设备执行。
- 未实现持久投递时明确标示通道限制，业务结果依赖权威记录回查，不宣称可靠交接已经完成。

**退出条件：** 签名篡改、跨租户、文件越界、无权限本地调用等拒绝场景通过；试点范围内无设备执行权限。

### 阶段二：可靠交接

- 确定并实现持久记录、投递确认、去重、有效期、查询恢复与受控重试。
- 补齐文件 manifest、接收凭据、背压、能力协商和准确就绪状态。
- 完成双方进程及 broker 的断网、重启、重复投递与存储失效验证。

**退出条件：** 已承诺的可靠性可通过故障注入验证；不丢失已持久接纳记录，不把未决或仅上传成功报为交接完成。

### 阶段三：受限设备执行通道

- 接入设备受限执行程序，绑定程序指纹、具体授权和控制权代次。
- Camind 负责控制权移交决策，设备端拒绝旧控制中心或旧代次的执行请求。
- 执行前重新验证授权、目标程序和实时开工条件。
- 先验证程序传输和接收凭据，再验证具备安全条件的远程启动。

**退出条件：** 目标设备完成安全与接口验收；过期、撤销、检查失效和结果未决场景均不会触发未经许可的新动作。单站点验收不自动授权其他站点。

## 8. 最小端到端验收矩阵

以下均为待实施的验收要求，不是本次审查已通过的测试结果。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 相同业务请求重复发送，双方重启 | 返回原状态，不重复产生业务副作用 |
| 相同业务 ID 携带不同内容 | 明确拒绝并保留关联信息 |
| 修改路由、租户、业务指纹或有效期 | 验签或协议检查失败，不进入业务执行 |
| 签名正确的旧消息重放 | 去重或过期拒绝，不重复投递动作 |
| 设备已启动但回执丢失 | 显示未决并查询，不自动重发启动 |
| 离线期间提交或恢复过期启动请求 | 拒绝，不在重连后补执行 |
| 节点被吊销、站点停用或控制权移交 | 旧端不能继续下达新动作；既有加工由设备本地安全策略处理 |
| 已受信任节点跨租户访问 | 消息、发现与文件访问被拒绝 |
| 对象内容被替换但存储层 digest 自洽 | 与发送方签名 manifest 不匹配，拒收 |
| 恶意文件名、符号链接、跨 bucket 或超大文件 | 无越界落盘、无未授权读取，错误可查询 |
| 磁盘满或持久化失败 | 不返回已持久接纳或已完成，不暴露半文件 |
| 文件落盘后 Adapter 通知失败 | 文件记录保留，可恢复通知，不重复执行文件对应业务 |
| NATS 或文件通道失效 | 就绪状态准确降级，不宣称仍具备原可靠性 |
| 并发积压与同设备多请求 | 资源有界，必要的设备动作顺序不被打乱 |
| 桌面窗口关闭、服务停止、主机休眠 | 窗口关闭不停止独立服务；服务不可用时不接受需在线执行的请求 |

协议和拒绝规则可由自动化回归验证；可靠性必须补充真实 daemon、NATS 和 Camind 接入端的故障注入。设备执行验收需使用经过授权且具备安全条件的现场设备，不能以 echo Adapter 或模拟回复代替机床凭据。

## 9. 实施涉及的主要位置

| 路径 | 主要改进方向 |
| --- | --- |
| `internal/protocol/` | 完整签名格式、版本、关联字段、回执与错误契约 |
| `internal/messaging/` | 持久交接、投递去重、有效期、状态查询、有界并发 |
| `internal/natsbus/` | 生产凭据、连接安全、所选可靠投递机制与状态暴露 |
| `internal/auth/`、`internal/trust/` | 身份与通信授权衔接、撤销一致性 |
| `internal/transfer/` | 签名 manifest、接收约束、配额、原子落盘、持久接收凭据 |
| `internal/store/` | 根据详细设计承载持久记录及原子写入，不提前确定新存储依赖 |
| `internal/adapter/` | Camind Webhook 受理语义、异步业务关联与确定性执行入口 |
| `internal/api/`、`internal/config/` | 本地访问保护、生产配置检查、状态与能力查询 |
| `cmd/`、`scripts/` | 诊断、版本固定与目标 OS 服务化 |
| `docs/` | 同步协议、部署、集成与可靠性限制说明 |

实现时保持小而明确的外部接口，将持久化、重试和恢复集中在通信模块内部；不要求每个调用方各自拼装一套通信恢复逻辑。业务幂等与设备安全决策仍由权威端负责。
